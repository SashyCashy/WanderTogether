- (decision) No accounts/login confirmed. Identity model: trips are accessed via a shareable trip code/link; each participant sets a freeform display name per trip (no persistent cross-trip identity, no auth).

- (assumption) Access control model is link-as-auth: anyone holding a trip's code/link can view and edit that trip, no per-member permission levels or ownership hierarchy in v1.
- (assumption) Shared itinerary editing uses simple last-write-wins, no real-time collaboration/locking/conflict resolution in v1.
- (assumption) Destination catalog is static/seed data curated by the builder; end users cannot add new destinations to the discovery catalog in v1.
- (assumption) No requirements from the tutor/assignment beyond the brief itself; PRD scaled to hobby/solo rigor (~2 pages) per stakes calibration.
