WanderTogether — UX Design Validation Report

_bmad-output/planning-artifacts/ux-designs/ux-WanderTogether-2026-09-27/

The spine pair is structurally sound and usable as a downstream contract: shape fit is textbook-correct, tokens are complete with real hex values, all four PRD user journeys have named Key Flows, and both files avoid bloat or source-restatement. Two categories are thin enough to cause real friction for a downstream consumer — Component coverage (4 of 8 components lack a DESIGN.md visual spec) and State coverage (the "My Trips" surface has no defined states at all, despite being a near-certain empty first-touch screen).

The accessibility lens shifts the picture materially: it found a critical color-contrast failure in the sage accent used for eyebrow labels and status tags (the one place the product communicates real state via color+text), plus a near-miss failure in the secondary "ink-soft" text color used almost everywhere. Several interaction patterns (hover-only row actions, the toggle switch, mobile nav collapse) are specified visually/behaviorally but never given the keyboard/ARIA semantics needed to actually meet the spine's own stated "Tab/Enter/Space" floor. None of this requires a rewrite — it's a punch list, and the disciplined parts of the spine (focus treatment, aria-describedby on errors, 44px touch targets, alt-text requirements) are already there.

Accessibility review

review-accessibility.md

Unusually disciplined on paper for a hobby project — but a hard contrast failure in the sage accent, a near-miss in secondary text, and several missing keyboard/ARIA equivalents are real, concrete gaps.

Critical

Sage accent fails contrast as text everywhere it's used

DESIGN.md colors, Typography.eyebrow, Components tags
accent #7C9885 on background/surface computes to ≈2.9:1 / ≈3.1:1, vs. 4.5:1 required. This is the eyebrow label color and the "open to buddies"/"Attached" status-tag color — the one place the product communicates real state via color+text.
Fix: darken to ~#5C7A67-#4E6B58 for any text use, or keep sage decoration-only and use ink for eyebrow/tag text.
High

Secondary "ink-soft" text narrowly fails AA

DESIGN.md colors ink-soft: #6C7A85
≈4.08:1 on background, ≈4.41:1 on surface — both under 4.5:1. Used for nearly all secondary/metadata copy in both mockups.
Fix: darken to ~#5C6B76 or darker.
High

Hover-revealed row actions have no keyboard fallback

EXPERIENCE.md Interaction Primitives
Touch fallback is stated (persistent icon); keyboard-focus fallback is not — a real WCAG 2.1.1/1.4.13 gap.
Fix: state that secondary row actions become visible on keyboard focus, identically to the touch treatment.
Medium

Mobile nav collapse has no accessible name/state spec

EXPERIENCE.md Responsive & Platform
No stated accessible name, aria-expanded, or focus management; mockup renders nav items as bare spans.
Fix: specify a real button trigger with a name, aria-expanded, and focus-into-menu on open.
Medium

Toggle switch lacks ARIA semantics and is under the min. target size

EXPERIENCE.md Component Patterns; mockups/trip-detail.html .switch
No role="switch"/checkbox semantics, no aria-checked, no associated label; 20px height is under SC 2.5.8's 24px minimum.
Fix: specify native-checkbox-styled-as-switch semantics and bump hit area to ≥24×24px.
Medium

Contradictory, and partly inert, input focus spec between the two files

DESIGN.md Components (inputs) vs. EXPERIENCE.md Accessibility Floor
DESIGN.md says focus "darkens the border," but the resting border is already ink-colored — nothing left to darken to.
Fix: delete the DESIGN.md line, or state EXPERIENCE.md's 2px outline supersedes it for inputs.
Medium

No live-region announcement for in-page state changes

EXPERIENCE.md State Patterns; Key Flow UJ-3
Accept/toggle-reveal changes content in place with no stated aria-live announcement for screen-reader users.
Fix: note that same-page updates are announced via a polite live region (WCAG 4.1.3).
Medium

Placeholder-only labeling on search and Trip Code fields

mockups/discover.html; EXPERIENCE.md Trip Code entry
No persistent visible label specified — a common real failure mode under 3.3.2.
Fix: require a persistent visible label for Trip Code entry and Discover search.
Low

Mockups use non-semantic markup with no implementer caveat

mockups/discover.html, trip-detail.html
Nav items as spans, toggle as a bare div — a developer could copy this structure verbatim.
Fix: one line near the mockup reference: "visual composition only; interactive elements must use real semantics per Accessibility Floor."
Low

No heading/landmark structure specified

EXPERIENCE.md Accessibility Floor
Neither file states nav landmark usage or heading hierarchy across sections.
Fix: not urgent; one sentence on a future pass.
