## Findings

### Aggregate view: duplication map

- **`ApiError` class and `throwForResponse` helper duplicated verbatim across every feature slice's `api.ts`.** Sourced: `grep -rln "class ApiError extends Error" apps/web/src` returns 5 files (`discover/api.ts`, `trip-detail/api.ts`, `buddies/api.ts`, `write-ups/api.ts`, `accommodations/api.ts`); 3 of those also duplicate an identical `throwForResponse`. The pattern originates in Epic 1: `trip-detail/api.ts` (Story 1.3) introduced it, and `discover/api.ts` (Story 1.2) was retrofitted to match it in that story's own `/code-review` pass ("`fetchDestinations()` threw a bare `Error`... unlike the `ApiError`/`throwForResponse` pattern Story 1.3 later established" — `spec-1-2-browse-and-filter-destinations.md`'s Review Triage Log). No single story's review flagged extracting a shared `shared/api.ts` module — each session correctly matched the established pattern but never consolidated it, and the same copy-paste repeated in every subsequent epic (3 more times in Epics 2–4). This is the exact "no single session saw the whole picture" case this retrospective exists to catch.

### Aggregate view: pattern divergence / process lesson

- **A single review pass systematically missed incomplete fixes to its own findings — this recurred independently in two different stories.** Sourced:
  - Story 1.4: the build-time review fixed `addMember`'s untrimmed `tripCode` lookup, but its own error message still interpolated the *untrimmed* value — caught only by the later, separately-invoked `/code-review` pass (`spec-1-4-...md`, "the earlier 'trim the code' fix was incomplete").
  - Story 1.5: the build-time review fixed a same-tab race by disabling new actions (`startEditing`/`removeItem`/"Add a line") while a save was pending, but missed that an *already-open* edit's own commit handler (`commitEdit`/`commitNewLine`) had no such guard — caught only by the later `/code-review` pass, and confirmed via the commit's own message: `98ed883 chore(story-1.5): address independent code-review finding`.
  
  Both gaps were the same shape: a guard added to *stop new actions* while a save is pending, but not to the *commit path of an action already in progress*. This is a real, sourced, twice-repeated pattern — not a one-off. It validates that this project's two-pass process (in-workflow review, then a separately-invoked `/code-review` against the finished commit) is load-bearing: the second pass caught defects the first pass's own fix introduced, in both cases. It also suggests a specific blind spot worth naming for future work: when a race-condition fix disables *starting* an action, check separately whether an *already-open* action's commit/save path needs the identical guard — the two are easy to conflate as "the same fix" and are not.

- **The "no frontend test runner exists for `apps/web`" gap was raised independently in nearly every story's review (1.2, 1.3, 1.4, 1.5, 1.6 — 5 of 6 stories) and never acted on.** Each review correctly triaged it as `low, reject (carried)` — a pre-existing condition from Story 1.1's scaffold, not a regression any single story introduced — which is a defensible per-story call every time. But at the epic level, a finding independently re-raised 5 times by 5 different review passes across 6 stories is a standing structural gap that no single story owns fixing. Carried forward through every later epic too (Stories 3.1–4.2 all found and correctly deferred the identical gap).

### Spec-to-implementation reconciliation

- **One item from Story 1.4's own deferred-work filing remains open and unaddressed as of Epic 1's completion:** no dedup guard exists against two `TripMember` rows being created for one physical "join" (double-click past the client-side pending-guard, network retry, or two tabs). Recorded in `deferred-work.md`, raised independently by two separate review passes within Story 1.4 alone. Still true today — `addMember` (`apps/api/src/features/trips/service.ts`) has no uniqueness constraint or idempotency key on `(tripId, displayName)`, by deliberate, documented design (freeform display names aren't a stable identity to dedupe against). This is an accepted deviation, not a defect, but it's worth carrying into this retrospective's record rather than only living in `deferred-work.md`, since it's genuinely epic-scoped open work.
